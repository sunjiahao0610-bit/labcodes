[SPECIFICATION]

1. init_main 与 user_main

Pre-Condition：
1.1 initproc 已创建并获得执行机会，用户程序二进制已嵌入内核镜像。

Post-Condition：
1.2 init_main 创建执行 user_main 的线程并等待其退出；user_main 启动指定用户程序。

Requirements：
1.3 使用 kernel_thread、do_wait 组织启动与等待流程。
1.4 使用工程现有 KERNEL_EXECVE 宏及 kernel_execve 加载用户程序，正确处理失败情况。

2. alloc_proc 与 kernel_thread

Pre-Condition：
2.1 进程管理和内存分配机制已初始化。

Post-Condition：
2.2 PCB 初始化正确，内核线程具有合法的初始执行现场。

Requirements：
2.3 补充用户进程所需字段，正确初始化 mm、进程状态及链表关系。
2.4 保留 Lab4 已实现的 trapframe 构造、do_fork 创建及首次运行机制，不破坏现有内核线程功能。

3. do_wait

Pre-Condition：
3.1 当前进程及父子关系有效。

Post-Condition：
3.2 正确等待子进程退出，获取退出码并完成僵尸进程回收。

Requirements：
3.3 正确处理指定 PID、等待任意子进程、子进程尚未退出及不存在等情况。
3.4 保证睡眠、唤醒、进程关系和资源回收一致，避免死等或重复释放。

4. kernel_execve

Pre-Condition：
4.1 当前处于 S 模式，具有有效内核栈，用户程序二进制合法。

Post-Condition：
4.2 成功时，当前进程通过异常返回路径进入 U 模式执行用户程序。

Requirements：
4.3 调用 do_execve 替换程序映像。
4.4 不能仅调用 do_execve 后普通 return，必须正确衔接 __trapret 或工程等价机制。
4.5 保证 trapframe、内核栈、sepc、sstatus 和 sp 的恢复关系正确，不额外创建 PCB。

5. do_execve

Pre-Condition：
5.1 当前进程有效，程序名称和二进制参数合法。

Post-Condition：
5.2 当前进程的旧程序映像被替换，新用户地址空间及执行现场准备完成。

Requirements：
5.3 正确处理旧 mm、页表及虚拟内存区域的资源释放。
5.4 调用 load_icode 装载新程序，更新 current->mm、页表和进程名称。
5.5 正确处理加载失败及资源清理，避免内存泄漏和状态不一致。

6. load_icode

Pre-Condition：
6.1 二进制文件有效，具备建立用户地址空间的条件。

Post-Condition：
6.2 ELF 程序、用户栈、页表及初始 trapframe 配置完成，可通过 sret 进入用户态。

Requirements：
6.3 解析 ELF 文件头和程序头，装载代码段、数据段并初始化 BSS。
6.4 建立用户虚拟内存映射和用户栈，正确配置 Sv39 页表及 PTE 权限。
6.5 设置 trapframe.epc 为 ELF 入口，trapframe.gpr.sp 为用户栈顶，并设置 SPP=0。
6.6 检查 ELF 合法性、段边界和资源分配结果，失败时清理已分配资源。
