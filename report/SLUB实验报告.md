# 任意大小的内存单元 slub 分配算法

## 一、主要算法与整体设计

本实验实现了一个简化的 SLUB 风格内存分配器，采用双层架构。

第一层复用现有物理内存管理器，实现基于页大小的内存分配。通过 `alloc_pages()`、`free_pages()` 等接口分配和回收完整物理页，保持当前 Best-Fit 实现及其检查不变。第二层提供 `kmalloc()`、`kfree()`，将按字节提出的内存请求转换为页面内部的对象分配或专用页块分配。

对于小对象，分配器设置了 16、32、64、128、256、512、1024、2048 字节八种规格。申请时选择能够容纳请求的最小规格，例如 24 字节请求使用 32 字节槽位。这样能够让多个对象共享页面，减少小对象独占整页造成的浪费，但规格取整仍可能产生内部碎片。

每种规格由一个 `slub_cache` 管理，其链表连接该规格的全部 slab。每个 slab 使用一页，页首保存管理记录，剩余空间划分为固定大小的对象槽位。分配器通过位图记录槽位状态：1 表示已分配，0 表示空闲。分配时优先复用已有 slab，只有没有可用槽位时才申请新页。

超过 2048 字节的请求使用专用连续页块。分配器将管理头和对齐开销计入空间需求，向底层申请足够的页面，并保存完整释放所需的页描述符和申请页数。

简化模型如下：

内核代码：按字节提出申请
SLUB 对象层：规格选择、槽位分配、对象释放、页面回收
现有 PMM：原有的按页分配和回收，当前使用 Best-Fit
八个规格 cache 分别维护 slab 链表，slab 内通过位图管理对象槽位；大对象通过独立链表记录页块归属。


## 二、主要功能的实现

### 2.1 数据结构与页面布局

`slub_cache` 保存对象规格及所属 slab 链表；`slub_slab` 保存链表节点、底层 `Page *`、槽位容量、已使用数量和分配位图；`slub_large` 保存大对象页块的链表节点、底层 `Page *` 和申请页数。

这些结构独立于原有 `Page` 描述符，没有借用其字段保存对象状态。

小对象页的布局为：

```text
[slab 管理记录][对齐空间][对象槽位……][不足一个槽位的尾部]
```

当前 RV64 构建中，`slub_slab` 大小为 72 字节，对齐后对象区从偏移 80 字节开始。各规格的槽位容量通过下式计算：

```text
capacity = (PGSIZE - SLUB_DATA_OFFSET) / object_size
```

整数除法向下取整，确保只使用完整槽位。固定的 32 字节位图能够记录最多 256 个槽位，足以覆盖当前最小规格。管理记录、位图和尾部空间均不会交给调用者使用。

| 对象规格（字节） | 每页容量（个） |
| --- | ---: |
| 16 | 251 |
| 32 | 125 |
| 64 | 62 |
| 128 | 31 |
| 256 | 15 |
| 512 | 7 |
| 1024 | 3 |
| 2048 | 1 |

这些容量对应当前结构布局，若管理结构发生变化，应重新计算。

### 2.2 关键函数及职责

| 函数 | 主要作用 |
| --- | --- |
| `slub_init()` | 初始化八种 cache 和大对象链表，检查布局约束，不提前申请物理页 |
| `slub_page_alloc()` | 封装既有页分配接口，保存 `Page *`，取得页面的内核虚拟地址 |
| `kmalloc()` | 处理零大小请求，并选择小对象或大对象分配路径 |
| `slub_new_slab()` | 为指定 cache 延迟申请一页，初始化管理记录、容量和位图 |
| `slub_small_alloc()` | 查找非满 slab，扫描位图分配空槽并更新计数 |
| `slub_large_alloc()` | 检查大小和页数计算，分配包含管理开销的连续页块 |
| `kfree()` | 从模块持有的链表中确定对象归属，再选择相应释放路径 |
| `slub_small_free()` | 校验槽位位置和状态，释放对象，并在 slab 全空时归还页面 |
| `slub_check()` | 组织接口、资源管理、异常处理及一致性测试 |

### 2.3 地址转换与小对象分配

`alloc_pages()` 返回的是物理页描述符指针，不能直接作为对象数据地址。实现通过已有 `page2pa()` 获取物理地址，再加上 `va_pa_offset`，取得直接映射区内可读写的内核虚拟地址。

小对象分配先确定规格，再遍历对应 cache 的 slab 链表，寻找满足 `inuse < capacity` 的页面。找到页面后，扫描位图中的空闲位，将其置为已分配并增加使用计数。对象地址由页起点、对象区偏移和槽位编号共同确定。

当已有页面均无可用槽位时，才创建新的 slab。这样可以优先复用现有空间，避免不必要的页分配。

### 2.4 大对象分配与溢出处理

大对象的管理记录位于专用页块开头。当前管理头对齐后占 32 字节，因此申请 5000 字节时，实际空间需求为 5032 字节，需要向底层申请两页。

实现先检查请求大小加上管理开销是否溢出，再通过商和余数计算页数，避免直接使用可能溢出的向上取整加法。底层申请失败时返回 `NULL`，不会将未完成的分配加入管理链表。

### 2.5 对象释放与页面回收

`kfree(NULL)` 不进行操作。对于非空指针，实现先在模块持有的 slab、大对象链表中确定归属，再读取相应管理信息。

小对象释放需要检查地址是否位于合法对象区、是否对齐到槽位起点，以及对应位图是否处于已分配状态。检查通过后清除分配位并减少使用计数。只要仍有活对象，slab 页面就继续保留；最后一个对象释放后，先摘除链表节点，再归还整页。

大对象释放要求传入原始返回地址。实现先保存底层页描述符和申请页数，摘除管理节点，再归还完整页块。页面归还之后不继续访问其中的管理记录。

本实现对有效 slab 内的管理区地址、尾部地址、槽位内部地址和重复释放进行诊断，并在修改状态之前触发 `panic`。

### 2.6 默认关闭与主线隔离

SLUB 使用 `ENABLE_SLUB_CHALLENGE` 控制，未定义或值为 0 时关闭，值为 1 时开启。模块实现、静态数据、初始化和测试调用均受该开关控制。

开启时，内核在既有 `pmm_init()` 及其检查完成后执行：

```c
slub_init();
slub_check();
```

关闭时保留原有启动流程，不改变 PMM 选择、页表机制和调试配置。验证结果表明，关闭配置的运行镜像及六个关键符号地址与新增 SLUB 前的基线一致。

### 2.7 接口约定

1. 本实现要求先完成物理内存初始化，再调用一次 `slub_init()`。
2. `kmalloc()` 以字节为单位接收请求；返回地址至少按 16 字节对齐，不承诺内容清零。
3. `kmalloc(0)`、资源不足或大小无法安全表示时返回 `NULL`。
4. `kfree(NULL)` 不进行操作；正常释放只接受本模块返回且尚未释放的原始地址。
5. 不支持任意部分释放，也不保证恢复任意野指针或页面回收后的悬空指针。
6. 支持范围限定为单核、串行调用，没有实现多核或中断重入的同步保护。

## 三、测试结果及有效性分析

测试通过独立的 API 调用记录、内部管理状态、对象数据和 PMM 空闲页数交叉验证，避免只根据“分配成功”或某一个内部计数判断正确性。

### 3.1 测试覆盖与检验依据

| 测试内容 | 结果 | 为什么能够有效检验实现 |
| --- | --- | --- |
| 初始化、零大小、NULL、规格边界及对齐 | 通过 | 相邻尺寸可检查规格选择边界；初始化前后页数比较可发现提前占页 |
| 多对象同时分配及完整数据写入 | 通过 | 比较活对象区间并检查请求范围内每个字节，可发现重复分配、重叠和数据破坏 |
| 槽位释放后复用 | 通过 | 保留同页其他对象，并禁止底层取得新页，重新申请仍成功，证明复用了已有槽位 |
| 跨 slab 增长、满页复用及单槽 slab | 通过 | 根据真实容量触发页面增长，检查计数和状态转换，覆盖容量为 1 的特殊情况 |
| 页面即时回收 | 通过 | 逐个释放对象，检查非空 slab 不还页、最后一个对象释放后页数恢复 |
| 大对象及管理头导致的跨页边界 | 通过 | 写满请求空间并检查跨页数据，同时核对页面占用，可发现遗漏管理开销和页数计算错误 |
| 受控取页失败及恢复 | 通过 | 检查失败返回值、活对象内容、管理快照和页数不变，验证失败路径不会留下半完成状态 |
| 内部一致性与 1000 次混合操作 | 通过 | 交叉检查位图、计数、对象记录、链表及页数，可发现连续操作中积累的状态错误 |
| 四类非法释放 | 符合预期 | 独立运行并实际触发对应 panic，比较报错前后的页面和缓存快照，验证先检查、后修改 |
| 默认关闭隔离 | 通过 | 比较关闭镜像、关键符号并运行原 PMM 检查，检验扩展没有改变默认实验路径 |

### 3.3 负面测试结果

四种负面模式分别覆盖管理区、槽位内部、页内尾部和重复释放：

| 模式 | 触发条件 | 预期诊断 |
| --- | --- | --- |
| 1 | 释放指向 slab 管理区的地址 | `SLUB: kfree points into slab management area` |
| 2 | 释放槽位内部地址 | `SLUB: kfree points inside a slot` |
| 3 | 释放页内尾部地址 | `SLUB: kfree points into slab tail` |
| 4 | 在 slab 仍有效时重复释放槽位 | `SLUB: kfree of an already free slot` |

测试保留同一 slab 中的另一个活对象，确保管理记录仍有效；通过 GDB 在 `__panic` 入口比较页面、缓存快照及空闲页数，确认报错前状态未改变。这里的 panic 是负面测试的预期结果，不是正常分配流程失败。

### 3.4 隔离验证

关闭配置的镜像与新增 SLUB 前的基线逐字节一致；`kern_entry`、`kern_init`、`boot_page_table_sv39`、`etext`、`edata`、`end` 六个关键符号地址保持一致。原有 Best-Fit 选择和 `check_alloc_page()` 检查正常，关闭构建没有额外 SLUB 输出。


### 3.5 复现方法

在已配置工具链的 WSL 环境中，进入工程 `code/` 目录执行。使用独立产物目录隔离开启配置：

```bash
# 默认关闭
make qemu

# 开启正向测试
make OBJDIR=obj/slub-check-positive BINDIR=bin/slub-check-positive \
  DEFS=-DENABLE_SLUB_CHALLENGE=1 qemu
```

负面测试分别令 `case_id` 为 1、2、3、4，独立运行：

```bash
case_id=1
make OBJDIR=obj/slub-check-negative-$case_id \
  BINDIR=bin/slub-check-negative-$case_id \
  DEFS="-DENABLE_SLUB_CHALLENGE=1 -DSLUB_CHECK_NEGATIVE=$case_id" qemu
```

每种宏配置使用不同构建目录，避免 Makefile 未跟踪宏变化导致旧对象文件被复用。看到完成信息或预期诊断后，可通过 QEMU 的 Ctrl-A、X 退出。

6.关闭扩展后，除比较镜像和关键符号地址，还必须运行原有启动流程，确认当前物理内存管理器的选择保持不变，且原有 check_alloc_page() 等检查仍成功。

slub_init

Pre-Condition：
1.扩展已启用，物理内存管理及其原有检查已完成。
2.SLUB 尚未初始化，不存在其分配的活对象。

Post-Condition：
1.各对象规格的管理状态有效，模块可以接受分配和释放请求。
2.不预先占用对象页面，底层空闲页数保持不变。

Requirements：
1.初始化不能依赖尚未就绪的 kmalloc，避免循环依赖。
2.本版本只要求初始化一次，不支持存在活对象时重新初始化。

kmalloc

Pre-Condition：
1.扩展已启用且 SLUB 已初始化。
2.size 表示请求字节数。

Post-Condition：
1.成功时返回至少可使用 size 字节的内核虚拟地址。
2.地址至少按 16 字节对齐，与其他活分配的存储区不重叠。
3.其他活对象的内容保持完整，不承诺新空间清零。

Case 1：零大小请求：
1.size 为 0 时返回 NULL，不改变状态或底层空闲页数。

Case 2：小对象请求：
1.小对象规格为 16、32、64、128、256、512、1024、2048 字节，使用能够容纳请求的最小规格。
2.每个小对象 slab 使用一页。
3.所选规格存在可用槽位时复用已有页面，不因本次请求额外申请页面。
4.分配后，对象状态、使用计数、可分配空间及 slab 归属保持一致。

Case 3：大对象请求：
1.超过小对象范围的请求使用专用连续页块。
2.可用空间满足请求，并正确计入管理信息及对齐开销。
3.保留仅凭原返回指针即可完整释放资源所需的信息。

Case 4：资源不足或请求不可表示：
1.无法满足请求，或大小、对齐、页数计算可能溢出时返回 NULL。
2.不损坏已有对象与管理结构，不遗留本次取得的资源。

Requirements：
1.管理信息不得与调用者可使用的空间重叠。
2.初始化布局及容量计算不得越过底层实际提供的内存范围。

kfree

Pre-Condition：
1.扩展已启用且 SLUB 已初始化。
2.正常调用的 ptr 为 NULL，或本模块返回且尚未释放的原始地址。
3.对当前仍有效的小对象 slab 内可识别的错误释放，按错误路径处理；不要求恢复任意野指针或页面回收后的悬空指针。

Post-Condition：
1.合法释放后，该空间不再属于调用者，可供后续复用或归还底层。
2. 其他活对象的内容、管理状态和资源归属保持有效。

Case 1：NULL：
1.直接返回，不改变状态。

Case 2：合法小对象：
1.对象不再处于已分配状态。
2.slab 尚有活对象时不得归还页面。
3.slab 已无活对象时，立即完整移除其管理归属并归还页面。

Case 3：合法大对象：
1.完整归还其专用页块，不遗留页面或指向已回收资源的管理记录。

Case 4：可识别的错误释放：
1.对有效 slab 内指向管理区、尾部、槽位内部的地址，以及已空闲的槽位，明确诊断并通过断言或 panic 终止。
2.报错前不得修改对象状态、空闲记录或计数。

Requirements：
1.页面归还后不得继续访问其中的管理记录。
2.对象状态记录不能依赖调用者必须保留的对象数据。

此外，关闭扩展后，复核既有 QEMU/GDB 调试流程及报告使用的关键断点。新增接入代码可能改变源码行号，因此若已有断点依赖固定源码行号，也需检查其定位仍然正确。不得通过修改报告或调试脚本掩盖兼容性问题。

slub_check

Pre-Condition：
1.扩展已启用，pmm、原有 PMM 检查和 SLUB 初始化均已完成。
2.无其他调用者并发分配或释放。

Post-Condition：
1.正向测试的关键结果经过断言或等价检查。
2.测试自行取得的资源全部释放，底层空闲页数恢复到测试基线。
3.只有全部检查通过才输出最终成功信息。

Case 1：初始化与接口边界：
1.验证 SLUB 初始化不提前占用对象页面。
2.覆盖各规格及相邻边界，特别是 16/17、32/33、2048/2049 字节。
3.验证空间满足请求、地址对齐及分类符合约定。
4.验证零大小、NULL 释放和极大 size_t 请求，不发生状态破坏或计算溢出。

Case 2：对象独立性：
1.同时持有多个对象，验证存储区互不重叠。
2.在请求范围内写入可区分数据，后续申请、释放其他对象后，仍存活对象的数据保持完整。

Case 3：空间复用：
1.在同一 slab 保留其他活对象，验证释放的槽位能够重新使用。
2.已有合适空闲槽位时，底层空闲页数不因再次申请减少。

Case 4：两层协同与状态转换：
1.根据真实容量触发跨 slab 增长，验证对象层按需向页级分配器取得页面。
2.验证满 slab 释放对象后可继续分配。
3.覆盖容量仅为一个对象的情况。
4.全部对象归还后，验证立即回收及底层空闲页数恢复。

Case 5：大对象：
1.覆盖 4096、5000 字节等请求，写满请求范围并检查跨页位置。
2.根据真实管理布局和 PMM 占用规则核对资源，不预设所有实现的管理区大小。
3.验证释放后完整归还专用页块。

Case 6：资源不足：
1.对确实需要新页面的请求实施受控故障注入。
2.验证返回 NULL、已有对象内容不变、状态有效且无泄漏。
3.故障解除后，合法分配能够恢复正常。
4.不允许通过破坏pmm数据结构来模拟失败。

Case 7：内部一致性：
1.检查对象使用数量、空闲数量、槽位唯一性、资源归属与 slab 状态一致。
2.结合返回地址、数据内容及独立资源计数交叉验证，不仅重复实现自身的计算。

Case 8：错误释放：
1.在 slab 仍有效且保留其他活对象时，验证管理区地址、槽位内部地址、有效页内越界槽位及重复释放被拒绝。
2.若错误路径会 panic，采用独立运行模式实际触发并验证预期诊断，不影响正向测试完成。
3.不通过访问已归还底层的页面验证错误释放。

Requirements：
1.测试记录使用固定空间或独立可靠的方式，不得无意消耗被测分配器，干扰容量与页数判断。
2.故障注入和测试辅助机制在默认关闭配置中不得产生运行代码或静态数据。
3.分别报告默认关闭配置、扩展开启配置及独立负面测试的实际结果。
