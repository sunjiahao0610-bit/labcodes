# 使用 gdb 调试页表查询过程
## 准备工作
编译（带调试符号）QEMU 源码（详见手册）

准备三个终端 A, B, C
首先在 A 中 `make debug` 启动 QEMU,然后在 B 中 ` make gdb `,接着

(gdb) c

接着在 C 中 通过 `pgrep -f "qemu-system-riscv64"` 查询到 QEMU 进程的 pid 后，执行 `sudo gdb`, `attach <pid>`，将 gdb 附着到 QEMU 进程上（当然，可以使用 `set remotetimeout unlimited` 避免一些~~莫名其妙的~~错误），最后：
```bash
# C
(gdb) b get_physical_address
Breakpoint 1 at 0x61bf89c440ce: file ../target/riscv/tcg/cpu_helper.c, line 1007.
(gdb) c
Continuing.
```
至此，万事具备，我们终于可以开始观察 `sd ra,8(sp)` 指令的运行了！

## 源码分析
QEMU 版本：
```c
QEMU emulator version 11.1.50 (v11.1.0-1860-gefa3b9d5ac-dirty)
Copyright (c) 2003-2026 Fabrice Bellard and the QEMU Project developers
```
代码来自 `target/riscv/tcg/cpu_helper.c`
```c
base = (hwaddr)get_field(env->satp, SATP64_PPN) << PGSHIFT;
vm = get_field(env->satp, SATP64_MODE);
```
从 `satp` 寄存器中提取出根页表的物理地址（存入 `base`），并读出当前的页表模式（比如 Sv39）。
```c
masked_msbs = (addr >> (va_bits - 1)) & mask;
if (masked_msbs != 0 && masked_msbs != mask) {
    return TRANSLATE_FAIL;
}
```
Sv39 要求虚拟地址的高 25 位必须是第 38 位的符号扩展（全 0 或全 1）。如果不满足，说明这是个非法地址。
```c
for (i = 0; i < levels; i++, ptshift -= ptidxbits) {
    idx = (addr >> (PGSHIFT + ptshift)) & ((1 << ptidxbits) - 1);
    pte_addr = base + idx * ptesize;
    pte = ... address_space_ldq_le(...);
```
- 计算索引（VPN）：把虚拟地址向右移位，并与掩码做与运算，剥离出当前级别的页表索引 idx。
- 计算 PTE 地址：当前页表基址 + idx * ptesize，这就是我们要去读的页表项的物理地址。
- 读取 PTE：通过 address_space_ldq_le 从物理内存中读出 ptesize 字节的页表项 pte。
```c
if (!(pte & PTE_V)) {
    return TRANSLATE_FAIL; // 页表项无效
}
if (pte & (PTE_R | PTE_W | PTE_X)) {
    goto leaf; // 找到了叶子节点（包含权限位）
}
// 如果不是叶子，当做下一级页表基址，继续循环
base = ppn << PGSHIFT;
```
- 检查读到的 PTE。最低位 V（Valid）必须为 1。
- 如果包含 R/W/X 任何一个权限位，说明是叶子节点（大页或普通页），直接跳出循环进入 leaf 标签（*本实验就是这种情况*）。
- 如果没有权限位，说明它指向下一级页表，把里面的物理页号（PPN）左移 12 位作为新的 base，继续下一轮循环。
```c
if (adue) {
    updated_pte |= PTE_A | (access_type == MMU_DATA_STORE ? PTE_D : 0);
}
// ... 原子写回 PTE ...
*physical = (((ppn & ~napot_mask) | (vpn & napot_mask) |
              (vpn & (((target_ulong)1 << ptshift) - 1))
             ) << PGSHIFT) | (addr & ~TARGET_PAGE_MASK);
```
- A/D 位更新：RISC-V 硬件会自动把页表项里的访问位（A）和脏位（D）置 1。QEMU 用 qatomic_cmpxchg 原子操作把这个修改写回物理内存，防止多核竞争。
- 计算最终物理地址：把页表项里提取出的物理页号（ppn），加上虚拟地址的页内偏移（及大页的中间位），拼接出最终的物理地址，写入 *physical。
