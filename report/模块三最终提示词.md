1. cpu_idle

Pre-Condition：
1.1 进程管理已初始化，current 指向有效的当前线程。

2. schedule

Pre-Condition：
2.1 proc_list、current 和 idleproc 均已正确初始化。

Post-Condition：
2.2 选择下一个可运行进程，必要时触发进程切换。
2.3 没有其他可运行进程时选择 idleproc。

Case 1：当前进程为 idleproc。
2.4 从普通进程链表头部开始查找处于 PROC_RUNNABLE 状态的进程。

Case 2：当前进程为普通进程。
2.5 从当前进程之后开始循环遍历，跳过链表头哨兵及不可运行进程，找到下一个符合条件的进程。

Case 3：没有找到其他可运行进程。
2.6 使用 idleproc 兜底；如果选中的仍是当前进程，避免不必要的切换。

Requirements：
2.7 正确处理 need_resched，并按照工程既有约定维护 runs 等调度信息。
2.8 使用已有中断保护机制保证调度关键操作的安全。
2.9 保持实验要求的简单循环查找策略，不新增复杂调度算法。

3. proc_run

Pre-Condition：
3.1 目标进程已正确初始化，具有合法的执行上下文和所需内存资源。

Post-Condition：
3.2 目标进程成为当前运行进程，CPU 使用相应的地址转换状态和执行上下文。
3.3 旧进程的上下文得到正确保存，能够在以后恢复执行。

Case 1：目标进程等于 current。
3.4 不执行不必要的上下文切换。

Case 2：目标进程不同于 current。
3.5 在受保护的关键区域内，保存旧进程引用、更新 current、处理目标进程页表状态，并调用 switch_to 完成切换。

Requirements：

3.9 注意内核线程与其他进程的地址空间表示可能不同，必须依据实际源码正确处理。

4. switch_to

Pre-Condition：
4.1 from、to 分别指向有效的旧进程与目标进程 context。
4.2 上层已完成调度选择和必要的切换准备。

Post-Condition：
4.3 旧进程需要保留的寄存器状态被保存到 from。
4.4 目标进程的相应寄存器状态从 to 恢复，CPU 转入目标进程的执行流程。

Case 1：目标进程首次运行。
4.5 恢复预先构造的 context，通过初始 ra 进入 forkret，并衔接已有的 trapframe 恢复流程。

Case 2：目标进程此前运行过。
4.6 恢复上次切换时保存的上下文，从原来暂停的位置继续执行。

Requirements：
4.7 遵守 RISC-V RV64 调用约定，正确保存和恢复 ra、sp、s0～s11。
4.8 寄存器的访存宽度及偏移必须与实际 struct context 布局一致。
4.9 正确使用 a0、a1 传递的 context 指针，保证寄存器保存、恢复和 ret 的执行顺序。
4.10 不在 switch_to 中实现调度策略、页表操作或 trapframe 恢复功能。
