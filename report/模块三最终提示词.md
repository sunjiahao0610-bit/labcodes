### 进程与执行现场

- `code/kern/process/proc.h` 中，`struct proc_struct` 的 `state`、`pid`、`kstack`、`context`、`tf`、`mm`、`pgdir` 保存子进程的调度状态与执行环境。`parent` 指向父进程，`cptr` 指向子链表的表头，`optr` 和 `yptr` 分别链接较旧和较新的兄弟节点。`list_link`、`hash_link` 分别挂入 `proc_list` 与 `hash_list`。当前进程由 `current` 指向。
- `code/kern/trap/trap.h` 中，`struct trapframe` 包含 `gpr`、`status`、`epc`、`tval`、`cause`。`gpr.sp` 保存栈指针，`gpr.a0` 保存返回值。现有用户态异常处理在分发系统调用前已推进 `epc`，`sys_fork` 将当前 `trapframe` 和其中的用户栈指针传给 `do_fork`。
- `code/kern/process/proc.c` 中，`alloc_proc()` 初始化 PCB，默认 `mm == NULL`、`pgdir == boot_pgdir_pa`。`setup_kstack(proc)` 和 `put_kstack(proc)` 管理子进程的内核栈。`copy_thread(proc, esp, tf)` 把现场复制到子进程内核栈，令子进程的 `a0` 为 `0`，根据 `esp` 设置恢复后的栈指针，并准备从 `forkret` 开始运行的内核上下文。`kernel_thread` 构造内核线程现场并传入 `stack == 0`。
- `get_pid()` 分配唯一 PID，`hash_proc(proc)` 注册 PID，`set_links(proc)` 在 `proc_list` 中登记进程、维护父子和兄弟关系，并递增 `nr_process`。`find_proc(pid)` 用于按 PID 查找进程。`wakeup_proc(proc)` 将子进程置为 `PROC_RUNNABLE`。`local_intr_save` 和 `local_intr_restore` 保存及恢复本地中断状态。

### VMA 与页表

- `code/kern/mm/vmm.h` 中，`struct mm_struct` 的 `mmap_list` 按起始地址排序，`mmap_cache` 缓存最近查到的 VMA，`pgdir` 是根页表的内核虚拟地址，`map_count` 统计 VMA 数量，`mm_count` 统计引用该地址空间的进程数，`mm_lock` 用于保护复制时读取的源地址空间。`struct vma_struct` 的 `vm_mm` 指向所属地址空间，`vm_start`、`vm_end` 表示半开区间 `[vm_start, vm_end)`，`vm_flags` 保存权限及栈标记，`list_link` 用于挂入 VMA 链表。
- `mm_create()` 创建空地址空间，其 `mm_count` 初始为 `0`。`setup_pgdir(mm)` 建立根页表并继承启动页表的内核映射，`PADDR(mm->pgdir)` 将根页表地址转换为 `proc->pgdir` 所需的物理地址。`lock_mm`、`unlock_mm` 保护源地址空间的遍历和复制。`mm_count_inc`、`mm_count_dec` 管理进程引用。`exit_mmap(mm)` 回收已登记 VMA 所覆盖的用户页映射及相应下级页表，要求 `mm_count == 0`。`put_pgdir(mm)` 回收根页表，`mm_destroy(mm)` 回收 VMA 描述符和 `mm`。
- `vma_create(vm_start, vm_end, vm_flags)` 分配 VMA 描述符，`insert_vma_struct(mm, vma)` 维护归属、升序、无重叠约束和 `map_count`。`le2vma(le, list_link)` 可从链表节点取得 VMA。`find_vma(mm, addr)` 查询包含给定地址的 VMA，命中后更新查询缓存。
- `get_pte(pgdir, la, false)` 查询 `la` 对应的 PTE，页表路径缺失时返回 `NULL`。`pte2page(pte)` 将有效 PTE 转换为页描述符，`page2kva(page)` 获得内核可访问的页地址。`alloc_page()` 分配一页，`free_page(page)` 释放尚未建立映射的页，`memcpy(dst, src, n)` 复制页内容。`page_insert(pgdir, page, la, perm)` 建立映射、维护页引用计数并使对应 TLB 项失效，页表分配失败时返回 `-E_NO_MEM`。`PTE_A` 和 `PTE_D` 由 `page_insert` 按工程现有约定设置。

本模块使用的宏以工程定义为准：

```c
// code/libs/unistd.h
#define CLONE_VM            0x00000100

// code/kern/process/proc.h
#define MAX_PROCESS 4096
#define MAX_PID (MAX_PROCESS * 2)

// code/kern/mm/mmu.h
#define PGSIZE 4096
#define PTE_V 0x001
#define PTE_USER (PTE_R | PTE_W | PTE_X | PTE_U | PTE_V)

// code/kern/mm/memlayout.h
#define USERTOP 0x80000000
#define USERBASE 0x00200000
#define USER_ACCESS(start, end) \
    (USERBASE <= (start) && (start) < (end) && (end) <= USERTOP)
```

`E_NO_MEM` 和 `E_NO_FREE_PROC` 定义于 `code/libs/error.h`，函数使用对应的负错误码。

## `do_fork`

**Pre-Condition**

- 进程管理与内存分配已初始化，`current` 是正在运行且 `wait_state == 0` 的父进程。`tf` 指向有效的执行现场。用户 fork 的 `stack` 为传入的用户栈指针，内核线程入口传入 `0`。

**Post-Condition**

- **Case 1｜创建成功**。子进程拥有独立的 PCB、内核栈、`trapframe` 和可用于首次调度的上下文。子进程关联到 `current`，持有唯一正 PID，已登记到 PID 哈希表、全局进程链表和进程树，并进入 `PROC_RUNNABLE`。父进程收到该 PID。用户子进程从父进程系统调用后的指令位置继续执行，从 `fork` 返回 `0`。内核线程按传入的内核现场启动。
- **Case 2｜进程数达到上限**。返回 `-E_NO_FREE_PROC`，进程登记和计数保持原状。
- **Case 3｜资源准备失败**。返回对应的负错误码，回收本次已取得的 PCB、内核栈和其他资源。失败的子进程未进入 PID 哈希表、进程链表、进程树及调度路径，父进程的现场和资源仍有效。

**Requirements**

- 先完成内核栈、地址空间和执行现场的准备，再登记子进程。PID 分配、哈希与链表登记、父子和兄弟关系更新以及计数变更应在同一处本地中断临界区完成。登记完成后才允许子进程变为可运行状态，状态切换沿用调度器的临界区保护。保持父进程 `wait_state == 0`，进程计数每次成功仅增加一次。

## `copy_mm`

**Pre-Condition**

- `proc` 是已初始化且尚未发布的子进程，`proc->mm == NULL`。父进程的 `current->mm` 为空，或指向具有有效根页表的用户地址空间。

**Post-Condition**

- **Case 1｜父进程无用户地址空间**。返回 `0`，子进程保留空 `mm` 和初始化时的启动页表物理地址。
- **Case 2｜父进程有用户地址空间且设置了 `CLONE_VM`**。返回 `0`，子进程引用父进程的 `mm_struct` 和同一根页表，共享地址空间的进程引用计数增加一次。
- **Case 3｜普通 fork 成功**。返回 `0`，子进程绑定独立的 `mm_struct` 和根页表，拥有与父进程对应的 VMA 和驻留用户页副本。新 `mm` 的进程引用计数为 `1`，父进程 `mm` 的引用计数及用户页映射保持原状。
- **Case 4｜复制资源不足**。返回 `-E_NO_MEM` 或下层返回的负错误码。已创建的用户页映射、页表、VMA 和 `mm` 按实际取得的资源回收，子进程仍处于未绑定用户地址空间的状态。

**Requirements**

- 复制源 VMA 和页映射期间持有源 `mm` 的锁，并在所有返回路径释放已取得的锁。新地址空间在复制完成前由创建路径独占，成功后才绑定给子进程。`proc->pgdir` 始终记录相应根页表的物理地址。共享分支须在子进程可调度前完成引用计数更新。

## `dup_mmap`

**Pre-Condition**

- `to` 和 `from` 是不同的有效 `mm_struct`，均已准备根页表。`to` 尚无 VMA 或用户映射，归调用方独占，`from` 由调用方加锁。源 VMA 按起始地址排列，各区间位于用户地址范围内、边界页对齐且互不重叠。

**Post-Condition**

- **Case 1｜复制成功**。返回 `0`。每个源 VMA 在 `to` 中有独立的对应描述符，区间边界和 `vm_flags` 相同，归属均为 `to`，链表仍按起始地址升序且无重叠，`map_count` 与实际数量一致。区间内已映射的用户页完成复制，空洞保持未映射。源 VMA 列表为空时，目标也保持为空并返回成功。
- **Case 2｜分配 VMA 或复制页面失败**。返回对应的负错误码。目标侧保留结构一致且可回收的中间状态，所有已建立的用户映射及为复制分配的页表都能由调用方按已登记的目标 VMA 回收，源 VMA 和映射保持原状。

**Requirements**

- 在某个区间开始建立目标映射之前，应先登记该区间的目标 VMA，使该区间发生部分失败时仍能由现有清理流程覆盖。目标链表、描述符及查询缓存由目标地址空间独立管理。

## `copy_range`

**Pre-Condition**

- `to` 和 `from` 指向不同根页表的内核虚拟地址。`[start, end)` 非空，两端按 `PGSIZE` 对齐且满足 `USER_ACCESS(start, end)`。目标区间内没有现有用户映射，源映射在复制期间保持稳定，目标页表由创建路径独占。普通 fork 调用时传入 `share == false`。

**Post-Condition**

完整处理指定区间后返回 `0`，其中每个虚拟页按源映射是否有效分别处理。

- **Case 1｜源页已映射**。为目标虚拟地址建立独立的物理页映射，复制源页完整的 `PGSIZE` 字节，保留源映射的用户访问和读、写、执行权限语义。源页内容、映射及引用计数保持原状，目标页引用计数由实际建立的映射维护。
- **Case 2｜源页表路径缺失或 PTE 无效**。跳过该空洞，目标对应地址保持未映射，也无需为该空洞分配物理页或新建下级页表。全为空洞的区间也可成功处理。
- **Case 3｜分配物理页或建立目标映射失败**。返回 `-E_NO_MEM` 或映射操作返回的错误码，并立即释放已分配但尚未建立映射的目标数据页。此之前建立的映射和目标页表保持可回收，由上层统一清理。

**Requirements**

- 保留 `share` 参数及现有逐页复制语义。整个地址空间的共享在 `copy_mm` 中完成。沿用正常的页表映射接口维护 PTE、引用计数和 TLB，按半开区间处理到 `end` 前的最后一页。
