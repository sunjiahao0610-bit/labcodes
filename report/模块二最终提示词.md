[SPECIFICATION]

1. alloc_proc()

Pre-Condition：

内核动态内存分配器已经初始化，可以为进程控制块分配内存。

Post-Condition：

成功时返回一个已完成基础初始化、尚未登记、尚未分配内核栈的 PCB；失败时返回 NULL，全局进程管理状态不变。

Case 1：分配成功

PCB 必须满足：
字段	初始值
state	PROC_UNINIT
pid	-1
runs	0
kstack	0
need_resched	false
parent、mm、tf	NULL
context	全部清零
pgdir	boot_pgdir_pa
flags	0
name	整个数组清零
list_link、hash_link	初始化为独立、尚未挂接的链表节点


Case 2：分配失败

返回 NULL，不得解引用无效指针，也不得修改进程计数、链表或全局进程指针。

Requirements：

本函数只建立基础 PCB，不分配 PID、不创建内核栈、不登记进程、不将其设置为可运行状态。
2. proc_init()

Pre-Condition：

在内核启动阶段调用一次。内存管理已经可用，启动栈和内核页表已经建立，进程管理尚未初始化。

Post-Condition：

正常返回时：
- 进程链表和全部 PID 哈希桶完成初始化。
- idleproc 和 initproc 均有效。
- current == idleproc。
- nr_process == 2。
- initproc 已登记并处于可运行状态，首次执行现场完整。
Case 1：初始化成功

将当前启动执行流包装为 idleproc，满足：
pid = 0
state = PROC_RUNNABLE
kstack = bootstack 的地址
need_resched = true
name = "idle"
parent = NULL
mm = NULL
tf = NULL
保留其尚未经历上下文切换时的零值上下文，并将其计入进程总数。遵循现有调度器约定，idleproc 不加入普通进程链表和 PID 哈希表。

建立 current 后，创建执行 init_main、参数为 "Hello world!!" 的内核线程。正常启动时，该线程应满足：
pid = 1
name = "init"
parent = idleproc
state = PROC_RUNNABLE
将其记录为 initproc，且能通过 PID 查询得到同一个 PCB。

Case 2：关键资源创建失败

创建 idleproc 失败或创建 initproc 返回错误时，使用现有内核错误处理机制终止初始化，不得继续解引用无效对象。

Requirements：
- 必须在创建 initproc 前建立有效的 current。
- idleproc 复用启动栈，不按普通新线程重新分配栈或构造陷阱帧。
- 保留现有初始化检查和断言。检查使用的临时内存应处理分配失败，并在使用完毕后释放。
- 本函数完成创建与登记，不直接执行 init_main()。
3. kernel_thread()

Pre-Condition：

进程管理已经初始化，current 有效。fn 是有效的内核函数入口；arg 可以为 NULL，其指向对象的有效期由调用方保证。

Post-Condition：

成功时返回新线程 PID，新线程能够在后续首次调度中执行 fn(arg)；失败时返回下层创建流程的负错误码。

Case 1：创建成功

构造初始陷阱帧，使其满足：
- 未使用的寄存器和状态字段具有确定的初值。
- gpr.s0 保存 fn 的地址。
- gpr.s1 保存 arg。
- epc 指向 kernel_thread_entry。
- 状态字段以当前 sstatus 为基础，置位 SSTATUS_SPP、SSTATUS_SPIE，清除 SSTATUS_SIE，保持其他位。
- 创建选项保留调用方传入的标志，并包含 CLONE_VM。
- 使用内核线程对应的零栈参数进入公共创建流程。
Case 2：创建失败

原样返回创建流程提供的负错误码，不留下可见的半初始化线程。

Requirements：

临时陷阱帧必须在函数返回前被复制到新线程拥有的存储空间，不能让新线程保存指向本函数局部变量的指针。本函数不得直接调用 fn。
4. do_fork()

Pre-Condition：

current 和进程管理全局结构有效。tf 指向有效的输入陷阱帧，调用期间保持可读。当前实验只支持内核线程地址空间，调用者应满足 current->mm == NULL。

Post-Condition：

成功时返回新线程 PID，并形成一个资源完整、登记完整、可被调度的进程；失败时返回负错误码，并释放本次创建已经取得的资源。

Case 1：进程数量达到上限

当进程总数已经达到 MAX_PROCESS 时，返回 -E_NO_FREE_PROC。不得为这次创建分配资源或改变已有进程状态。

Case 2：创建成功

新进程必须具有：
- 完成初始化的 PCB。
- 指向创建者的 parent。
- 独立分配的内核栈。
- 符合当前实验约定的地址空间信息。
- 位于自身内核栈中的陷阱帧，以及正确的首次切换上下文。
- 范围合法、与已有进程不冲突的 PID。
- 进程链表和 PID 哈希表中各一份有效登记。
- PROC_RUNNABLE 状态。
进程总数只增加一次。通过返回的 PID 查询，应得到此次创建的 PCB。创建流程不得修改输入陷阱帧，也不得主动切换 current。

Case 3：PCB 分配失败

返回 -E_NO_MEM，不修改进程登记结构和进程计数。

Case 4：内核栈或后续准备步骤失败

释放已经取得的资源，返回相应负错误码。内核栈分配失败时只释放 PCB；内核栈已经建立后再失败时，应释放栈和 PCB。不得释放调用者的栈、输入陷阱帧或已有进程资源。

Requirements：
- 新进程在资源和执行现场准备完成前，保持不可运行状态。
- PID 分配、链表登记和进程计数更新必须通过现有中断控制接口保护，避免可被观察到的不一致状态。
- 完成全部登记后才能将新进程设为可运行。
- 发生错误时不得遗留链表节点、错误计数、内存泄漏或重复释放。
- 所有经过中断保护的返回路径都必须恢复原来的中断状态。
- 当前 copy_mm() 不会创建用户地址空间资源，不添加尚未使用的用户地址空间回收逻辑。
5. copy_thread()

Pre-Condition：

proc 指向已初始化但尚不可运行的新 PCB；该进程已经拥有大小为 KSTACKSIZE 的内核栈。输入 tf 有效，esp 为 0 或调用方提供的有效初始栈指针。

Post-Condition：

新进程拥有独立的陷阱帧副本，以及能够进入首次运行链路的上下文。输入陷阱帧保持不变。

陷阱帧地址必须满足：
proc->tf == (struct trapframe *)
    (proc->kstack + KSTACKSIZE - sizeof(struct trapframe))
陷阱帧内容来自输入副本，其中 gpr.a0 设为 0，gpr.sp 按下面的情况确定。

PCB 中的上下文必须满足：
proc->context.ra == (uintptr_t)forkret
proc->context.sp == (uintptr_t)proc->tf
Case 1：esp == 0

新线程使用内核栈，陷阱帧中的初始 sp 设为该线程自身陷阱帧的地址。

Case 2：esp != 0

陷阱帧中的初始 sp 使用调用方提供的 esp。用于首次上下文切换的 context.sp 仍指向新线程自己的陷阱帧。

Requirements：
- 陷阱帧必须完整落在已分配的内核栈范围内，保持现有 ABI 所需对齐。
- 保留输入陷阱帧中的入口、状态和函数参数等信息，仅修改本函数明确规定的字段。
- context 保存在 PCB 内，不另行分配或复制到内核栈。
- 本函数不分配 PID、不登记进程，也不改变进程运行状态。
6. copy_mm()

Pre-Condition：

current 有效，proc 指向初始化完成的新 PCB。当前实验处理内核线程，创建者和新进程均不拥有用户地址空间。

Post-Condition：

合法调用返回 0，新进程保持 mm == NULL，继续使用初始化时设置的内核页表。不得分配、复制或释放用户地址空间资源。

Case 1：当前进程没有用户地址空间

完成当前实验要求的条件检查，返回成功，保持现有地址空间信息。

Case 2：当前进程具有用户地址空间

通过现有断言暴露当前实验不支持的调用条件，不能静默返回成功。

Requirements：

保留 clone_flags 和 proc 参数及完整函数接口，为后续实验扩展共享或复制地址空间留下接口。本阶段不实现这些扩展功能。
