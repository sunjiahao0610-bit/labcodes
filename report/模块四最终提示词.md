### 进程状态与调度

- `code/kern/process/proc.h` 中，`current` 指向当前进程，`idleproc` 和 `initproc` 是受保护的内核进程。`struct proc_struct` 的 `state`、`flags`、`volatile bool need_resched`、`wait_state` 和 `exit_code` 分别记录进程状态、标志、调度请求、等待原因和退出码。`parent` 指向父进程，`cptr` 指向子链表表头，`optr` 和 `yptr` 分别链接较旧和较新的兄弟节点。
- `find_proc(pid)` 查询 PID 哈希表，合法查询范围为 `0 < pid && pid < MAX_PID`，查找不到时返回 `NULL`。`wakeup_proc(proc)` 将可唤醒的进程置为 `PROC_RUNNABLE` 并清除其等待状态，要求目标处于非僵尸态。`schedule()` 清除调用进程的 `need_resched`，从进程链表中选择可运行进程。`code/kern/sync/sync.h` 中的 `local_intr_save` 和 `local_intr_restore` 保存并恢复本地中断状态。
- `code/kern/trap/trap.c` 中，用户态异常返回路径检查 `need_resched` 和 `PF_EXITING`。调度请求在该路径交给 `schedule()`，退出请求由 `do_exit(-E_KILLED)` 处理。`do_wait` 从可中断的等待中被唤醒后也会检查 `PF_EXITING`，并在发现退出请求时走同一退出入口。

### 地址空间与等待回收

- `current->mm` 指向当前进程的用户地址空间，内核线程可以持有空 `mm`。`mm->pgdir` 是根页表的内核虚拟地址，`current->pgdir` 保存根页表物理地址。`lsatp(boot_pgdir_pa)` 切换到启动页表，`mm_count_dec(mm)` 减少地址空间的进程引用并返回更新后的计数。
- `exit_mmap(mm)` 在 `mm_count == 0` 时回收用户页映射和相应的下级页表。`put_pgdir(mm)` 释放根页表，`mm_destroy(mm)` 释放 VMA 描述符及 `mm_struct` 本身。启动页表用于继续执行内核清理代码。
- `do_wait(pid, code_store)` 按 PID 或从子链表查找僵尸子进程，并通过 `user_mem_check(mm, (uintptr_t)code_store, sizeof(int), 1)` 检查非空的退出码写入地址。它读取 `exit_code`，调用 `unhash_proc`、`remove_links` 摘除进程登记并更新进程计数，最后释放子进程内核栈和 PCB。`do_exit` 与这套回收约定配合。

本模块使用以下源码定义。

```c
// code/kern/process/proc.h
#define PF_EXITING 0x00000001
#define WT_CHILD (0x00000001 | WT_INTERRUPTED)
#define WT_INTERRUPTED 0x80000000

// code/libs/error.h
#define E_INVAL             3
#define E_KILLED            9
```

## `do_exit`

**Pre-Condition**

- 进程管理和调度器已初始化。`current` 指向正在执行的进程。可退出进程具有有效的父进程关系，且它持有的非空 `mm` 具有有效引用。`error_code` 是要交给等待者的退出码。

**Post-Condition**

- **Case 1｜当前进程是 `idleproc` 或 `initproc`**。按内核现有的 `panic` 约定拒绝退出，在处理地址空间或进程状态前报告该错误。
- **Case 2｜当前进程可以退出**。有用户地址空间时，先切换到启动页表，归还当前进程持有的引用并清空 `current->mm`。最后一个引用释放时回收旧地址空间，共享者仍持有引用时继续使用该地址空间。无用户 `mm` 时直接进入进程状态的处理。随后原样保存退出码，清除退出进程的等待状态，置为 `PROC_ZOMBIE`，通知正在以 `WT_CHILD` 等待的父进程，最后由调度器切换到其他进程。退出进程的执行到此结束，其父进程通过 `do_wait` 完成最终回收。
- **Case 3｜可退出进程还有子进程**。按正常退出流程处理，并将它的全部子进程交给 `initproc`，修正 `parent`、`cptr`、`optr`、`yptr`。若移交的子进程中已有僵尸且 `initproc` 正在等待子进程，唤醒 `initproc`，使其能继续回收。

**Requirements**

- 在公布僵尸状态之前完成当前进程的地址空间处理。释放旧根页表前，硬件使用的页表和 PCB 记录的页表地址都应指向启动页表。每次退出只归还当前进程持有的一份 `mm` 引用。
- 保存退出码、清除等待状态、公布僵尸状态、迁移子进程关系和通知等待者，应在同一处本地中断临界区完成。被唤醒的等待者应能看到退出码和完整的进程关系。僵尸进程的 PID 登记、进程链表项、内核栈和 PCB 由 `do_wait` 最终回收。

## `do_yield`

**Pre-Condition**

- 调度器已初始化，`current` 指向当前正在执行的可运行进程。

**Post-Condition**

- 将 `current->need_resched` 置为真并返回 `0`。当前进程保持可运行，调度器在现有调度点根据可运行进程选择下一次执行者。已提出的调度请求可与再次让出合并。

**Requirements**

- 沿用现有异常返回和调度边界。`do_yield` 只提交重新调度请求，`need_resched` 由调度器处理并清除。

## `do_kill`

**Pre-Condition**

- 进程管理和 PID 哈希表已初始化。`pid` 是调用者传入的目标 PID，是否有效由该函数判定。

**Post-Condition**

- **Case 1｜目标不存在或受保护**。PID 超出有效范围、查找不到目标，或目标是 `idleproc`、`initproc` 时返回 `-E_INVAL`。
- **Case 2｜目标已是僵尸或已有退出请求**。返回 `-E_KILLED`，保留先前的退出请求或已经公布的退出结果。
- **Case 3｜目标可以接收退出请求**。在原标志上设置 `PF_EXITING` 并返回 `0`。若目标处于 `PROC_SLEEPING` 且其 `wait_state` 含有 `WT_INTERRUPTED`，唤醒它以处理退出请求。处于不可中断等待的目标继续等待原有唤醒条件。目标到达现有退出检查点时，自行执行 `do_exit(-E_KILLED)`。

**Requirements**

- 在同一处本地中断临界区完成 PID 查找、目标状态检查、设置退出标志和必要的唤醒，使标志与唤醒状态对调度器一致可见。所有返回路径都恢复进入时的中断状态。目标进程通过 `do_exit` 处理地址空间和退出状态，等待者通过 `do_wait` 完成最终回收。
